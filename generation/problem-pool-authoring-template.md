# GamjaOJ 기본 문제 풀 확장 — 120문제 출제 템플릿

일반 문제 목록에 등록할 기본 연습 문제를 작성하기 위한 요청서다.
진단평가에서 좋은 평가를 받은 문제의 명확한 규칙·경계 테스트·오답 검증 방식을 참고한다.
난도와 알고리즘 범위는 일반 연습 문제 목적에 맞춘다.

현재 구현 기준: 2026-10-02, 코드 커밋 `18d99b9`.

## 문제 수와 카테고리

**10개 카테고리 × 3개 난도 × 난도별 4문제 = 총 120문제.**
한 카테고리에 하 4개·중 4개·상 4개, 총 12개를 작성한다.
각 난도의 네 문제는 서로 다른 학습 목표와 실수 유형을 다룬다.

아래 10개는 현재 혼합 알고리즘 진단에 쓰이는 분야 구성을 기준으로 잡았다.
공개 목록에는 한글 분야명을 저장한다. 영문 ID는 작성 패키지의 분류·파일 관리에만 사용한다.

같은 문제에 여러 효율적인 풀이가 있으면 모두 허용한다.
분야가 겹치는 문제는 핵심 학습 목표에 따라 대표 분야 하나를 정하고 보조 기술은 태그에 넣는다.
하·중·상은 해당 분야 안에서의 상대 난도다. 다른 사이트의 등급으로 단정하지 않는다.

추가 확장 후보는 구현·시뮬레이션, 정렬, 수학·정수론, 트리, 기하다. 위 120문제에는 포함하지 않는다.

```text
- 세 언어를 지원하는 일반 문제는 표준 입력/표준 출력 방식으로 작성한다.

[문제마다 납품할 자료]

   적용되지 않는 사항을 억지로 추가하지 않는다.
   정답 알고리즘 이름·점화식·핵심 상태 압축·숨은 테스트 설명을 본문에 누설하지 않는다.
3. 공개 예제 3개와 각 예제 설명.
   정상 흐름과 주요 규칙을 실제로 보여주는 서로 다른 입력을 선택한다.
   같은 답 0 또는 -1만 반복하거나 선택 입력이 있는 문제에서 항상 선택 개수 0만 보여주지 않는다.
   첫 테스트는 첫 공개 예제와 일치시키고, 나머지 예제도 고정 테스트에 포함한다.

4. 비공개 고정 테스트와 각 테스트의 설계 이유.

9. 비공개 해설: 핵심 관찰, 정확성 근거, 다른 올바른 풀이, 시간/공간 복잡도,

    검사 완료/추정/미검증을 구분한 결과.

[검증 기준]
- 본문·제약·예제·validator·oracle·세 언어 코드·모든 테스트를 서로 대조한다.
- 작은 전수/랜덤 입력에서 oracle과 세 언어 정답을 비교한다.
- 실제 GamjaOJ Runner와 고정 실행 이미지에서 모든 정답이 AC인지 확인한다.
- 최대 크기 및 가장 까다로운 구조를 실제 입력으로 만들어 시험한다.
- 효율 문제는 가장 강한 현실적인 단순 풀이를 검토한다. 일부러 틀리거나 느린 코드만 상대하지 않는다.
- 최종 언어별 시간 제한에서 다시 검증한다. 다른 시간 제한에서의 TLE를 그대로 재사용하지 않는다.
- 정답 실행에는 여유를 둔다. Java는 적어도 관측 최대 wall time의 2배를 확보하고,
  다른 언어도 실제 관측과 변동성을 근거로 정한다. 미측정 언어는 추정이라고 명시한다.
- 메모리는 호스트에서 관측한 컨테이너 cgroup peak다. heap/RSS와 동일하다고 쓰지 않는다.
  미측정 값을 0으로 만들지 않는다. Java heap과 Python 객체 메모리 추정도 따로 기록한다.
- 도구를 사용할 수 없으면 검증 코드를 제공하되 실행 결과와 숫자를 지어내지 않는다.
- 실패하면 본문·코드·테스트 중 원인을 수정해 관련 검증을 다시 수행한다.
  조용히 범위를 줄이거나 규칙·학습 목표를 빼서 통과시키지 않는다.

[납품 방식]
- 먼저 전체 목록을 ID/분야/난도/제목/핵심 목표/핵심 풀이/다양성 근거 표로 제출한다.
- 이후 한 묶음은 한 분야·한 난도의 정확히 네 문제다. 전체를 한 응답에 압축하지 않는다.
- 묶음마다 manifest.json, 공개 statement.md, 비공개 package.json, 정답/오답/느린 풀이,
  oracle/validator/generator, 고정 테스트 파일, 검증 스크립트와 보고서를 제공한다.
- manifest는 납품 목록이다. 현재 서버 API나 기존 진단 적재기가 이 형식을 자동으로 받아준다고 주장하지 않는다.
- 문제 등록 담당자가 일반 problem_version과 공개 카탈로그 메타데이터로 변환할 수 있게 구분한다.
- 진단 문항 ID/묶음을 재사용하지 않는다. diagnostic_only=false인 일반 연습 문제 후보로 납품한다.
- 공개 본문과 예제만 학습자에게 제공하고 숨은 테스트·정답 코드·seed·비공개 해설은 서버 측에 보관한다.
- 미완성 코드, 생략된 정답 출력, '나머지는 비슷하게', 통과를 꾸며낸 보고서는 납품하지 않는다.
```

## 납품 파일 구성

아래는 작성자와 등록 담당자 사이의 **납품 형식**이다. 현재 자동 import API의 명세가 아니다.
후보의 공개 여부는 실제 Runner·내용 검토를 마친 뒤 일반 문제 등록 경로에서 결정한다.

```text
basic-pool-v1/
  plan.csv                         # 120개 전체 계획
  manifest.json                    # 이번 묶음의 네 문제, 경로, 파일 해시, 검증 상태
  problems/<slug>/
    metadata.json                  # 분야/태그/난도 및 시간 제한 제안
    statement.md                   # 공개 본문과 예제 설명
    package.json                   # 아래 Runner 패키지
    teaching.md                    # 비공개 해설/힌트/정확성·효율 근거
    tests/<test-id>.in
    tests/<test-id>.out
    solutions/java/Main.java
    solutions/cpp/Main.cpp
    solutions/python/Main.py
    mutants/<name>/...             # 완전한 오답 프로그램
    slow/...                       # 효율 검증이 필요한 경우
    qa/oracle.py
    qa/validator.py
    qa/verify.py
    generated/Main.java            # 필요한 경우, seed → 입력
    verification.json              # 실제 수행 또는 미검증 표시
```

### 메타데이터 필드

- `slug`: 영문 소문자·숫자·하이픈으로 만든 고유 이름.
- `version`: 예를 들어 `basic-pool-v1-dp-medium-01-v1`. 80자 이내, 기존 버전 덮어쓰기 금지.
- `categoryId`: 위 표의 내부 ID. 공개 DB 분야에는 `category`의 한글 값을 사용한다.
- `category`: 대표 한글 분야.
- `tags`: 한글 보조 기술, 최대 6개.
- `difficulty`: `EASY`, `MEDIUM`, `HARD` 중 하나. 별도로 근거를 기록한다.
- `timeLimits`: `JAVA`, `CPP`, `PYTHON`, `analysis`를 가진 문항별 제안. 아직 적용되지 않은 제안은 그렇게 표시한다.
- `verificationStatus`: 실제 실행 여부와 실패·미검증을 구분한다. 후보를 검증 완료로 미리 표시하지 않는다.

### Runner package.json 형태

아래는 필드 구조 예시다. 꺾쇠 안 내용은 실제 출제 결과로 모두 바꾼다.
`category`, `difficulty`, `timeLimits`, 검증 보고서와 납품 파일 경로는 별도 메타데이터에 둔다.

```json
{
  "version": "basic-pool-v1-dp-medium-01-v1",
  "title": "<한국어 제목>",
  "statement": "<한국어 본문·입력·출력·제약>",
  "output_policy": "TOKEN_EXACT",
  "samples": [
    {"input": "<예제 1 입력>\n", "output": "<예제 1 정답>\n"},
    {"input": "<예제 2 입력>\n", "output": "<예제 2 정답>\n"},
    {"input": "<예제 3 입력>\n", "output": "<예제 3 정답>\n"}
  ],
  "tests": [
    {"id": "sample-01", "input": "<예제 1 입력>\n", "output": "<예제 1 정답>\n"},
    {"id": "sample-02", "input": "<예제 2 입력>\n", "output": "<예제 2 정답>\n"},
    {"id": "sample-03", "input": "<예제 3 입력>\n", "output": "<예제 3 정답>\n"},
    {"id": "boundary-01", "input": "<비공개 입력>\n", "output": "<비공개 정답>\n"}
  ]
}
```

대형 생성 테스트가 필요할 때만 같은 객체에 다음 `generated` 필드를 추가한다.
`generator`와 `reference`는 파일 경로가 아니라 완전한 Java 8 소스 문자열이다.

```json
{
  "generated": {
    "generator": "<Java 8 생성기 전체 소스>",
    "reference": "<Java 8 정답 전체 소스>",
    "tests": [
      {"id": "large-seed-11", "seed": "11", "expected": "REFERENCE"},
      {"id": "large-seed-12", "seed": "12", "expected": "REFERENCE"}
    ]
  }
}
```

## 실행·등록 시 확인할 점

- 120문제의 계획은 한 번에 잡고 실제 제작은 **네 문제씩 총 30묶음**으로 진행한다.
- 예제 설명은 공개 statement.md에 포함한다. `samples`의 임의 설명 필드만으로 화면 표시를 기대하지 않는다.
- 위 문제 형식은 세 언어를 지원하는 STDIO 경로다. 함수형 API 문제를 만들 때는 별도의 callable/driver 계약이 필요하며 이 템플릿 범위에는 없다.
- 예전 진단 작성 가이드의 고정 시간 제한 설명보다 현재 `runner/languages.json`, `runner/judge.py`,
  `ProblemTimeLimits.java`, `Submissions.java`의 계약을 우선한다.
- 생성기는 정답을 입력에 섞어 출력하지 않는다. 입력은 생성기, 정답은 reference가 각각 출력한다.
- 공개 예제·비공개 테스트 출력은 ASCII `-` 등 실제 출력 문자와 일치시킨다. 인쇄용 다른 마이너스 문자를 섞지 않는다.
- 숨은 테스트·정답 코드·비공개 해설이 포함된 납품물은 공개 저장소나 frontend assets에 넣지 않는다.
- 이 파일은 출제 요청서다. 실제 120문제 생성·모델 호출·DB 등록·공개가 완료됐다는 의미는 아니다.
